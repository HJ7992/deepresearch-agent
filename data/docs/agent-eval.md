# Agent 评测方法

Agent 的评测比单轮问答难：输出是长链路、非确定的，同一个问题多次运行结果可能不同。因此评测要固定任务集、固定模型版本、多次运行取统计量，并把成本与延迟一起记录。

## 常用指标

- **任务成功率**：在固定任务集上，人工或规则判定「是否完成」。最核心的指标。
- **步骤效率**：完成同一任务所需的模型调用次数/工具调用次数，反映是否绕路。
- **引用准确率**：报告中的引用是否真实存在于资料库，以及引用内容是否支持结论。
- **成本与延迟**：单任务 token 消耗、估算费用、端到端耗时。
- **鲁棒性**：换措辞、加噪声、给错误前提时是否仍能正确应对。

## 评测方法

1. **固定评测集**：20-30 个有代表性、可判定对错的任务，覆盖简单/中等/困难。
2. **规则判定优先**：能用程序判断的（引用编号是否存在、格式是否合规）不要交给模型。
3. **LLM-as-judge 兜底**：主观质量用另一个模型按评分标准打分，需固定评分提示词并抽样人工校准。
4. **消融实验**：一次只改一个变量（如开/关记忆、开/关引用核验），对比指标变化，证明每个模块的价值。
5. **回归测试**：每次改提示词或流程后重跑评测集，防止指标回退。

## 常见误区

只看单次演示效果而不做统计；用自己写的题目自评；把「模型说通过了」当作通过。评测集和脚本应进仓库，保证结果可复现。
