# RAG（检索增强生成）基础

RAG（Retrieval-Augmented Generation）是在生成前先从外部知识库检索相关片段、再把片段注入上下文的一种架构。它不改变模型参数，因此知识更新只需重建索引，不必重新训练。

## 典型流程

1. 文档切块：把长文档按语义或长度切成片段，常见 300-800 字符，块间可保留重叠。
2. 嵌入：用嵌入模型把片段转成向量。
3. 入库：向量写入向量数据库（如 Qdrant、Milvus、pgvector），并保存来源等元数据。
4. 检索：把用户问题嵌入后做相似度检索，取 Top-K；可再加一层重排（reranker）提升精度。
5. 生成：把检索片段与问题一起交给大模型，要求基于片段作答并标注来源。

## 优点与局限

优点是知识可更新、答案可溯源、比微调便宜，且能按权限过滤文档。局限是效果高度依赖检索质量：切块不当、嵌入模型不匹配、召回不足都会让生成结果变差；上下文窗口有限，片段太多会推高成本与延迟；对需要改变模型行为（语气、格式、指令遵循）的任务，RAG 无能为力。

## 与微调的区别

RAG 解决「模型不知道最新/私有事实」的问题，微调解决「模型行为不符合要求」的问题。实践中常见组合是：先用提示词 + RAG 建立基线并评测，若事实性达标但风格或格式不稳定，再考虑微调。
