# 学习指南：怎么把这个项目真正变成「你的」

> 代码大部分由 AI 辅助生成，这不可耻——但面试官追问三层时，你必须答得出来。
> 建议按下面的顺序学，每一步都有可检验的产出。

## 第一步：跑起来（半天）

```bash
uv venv --python 3.12 && uv sync --extra dev
.venv/Scripts/python -m pytest -q          # 36+3 个测试全绿
.venv/Scripts/python -m deepresearch.ingest data/docs
.venv/Scripts/python -m deepresearch.main "RAG 和微调应该怎么选？"
```

产出：你能不看文档独立跑通，并解释 `data/docs` 里的语料怎么变成检索结果。

## 第二步：读代码（2–3 天，按依赖顺序）

| 顺序 | 文件 | 你要能回答 |
|------|------|-----------|
| 1 | `state.py` | 每个字段谁写？为什么要 reducer？ |
| 2 | `graph.py` | 节点/边/条件边各是什么？Send 在哪扇出？路由四个条件？ |
| 3 | `nodes.py` | researcher 为什么只拿 `sub_question`？collect 为什么要重编号？ |
| 4 | `structured.py` | 三种模式区别？降级怎么触发？ |
| 5 | `retriever.py` + `chunking.py` | 切块策略？本地/服务端模式？ |
| 6 | `checkpointer.py` + `runner.py` | checkpoint 存哪？resume 为什么只跑后半段？ |
| 7 | `api.py` / `mcp_server.py` | 为什么异步任务？MCP 工具怎么分工？ |
| 8 | `eval/run_eval.py` | 指标怎么算？消融怎么做？ |

配合 `docs/验收题.md`（20 题带答案要点）自测：遮住答案，口述一遍。

## 第三步：手写重实现（每项 1–2 小时）

闭卷、不看源码，从零写出来，再对照差异：

1. `make_researcher(llm, retriever)` —— 检索、编号、prompt 组装
2. `collect` 节点 —— 排序、去重、两段式重编号
3. `route_after_critic` —— 四个条件 + 封顶
4. `make_verifier` —— 段落切分、引用提取、覆盖率计算
5. `make_human_gate` —— interrupt / resume 语义

写完跑 `pytest` 验证；这五个函数覆盖了项目 80% 的面试追问点。

## 第四步：改一个真实需求（1 天）

选一个，自己动手改，跑测试和评测：

- 把 `data/docs` 换成你熟悉的领域文档（比如某框架官方文档），重建索引，
  看关键词命中率变化，解释为什么；
- 把 `chunk_text` 的 `max_chars` 从 600 改成 300 / 1200，重跑 3 题评测，
  对比覆盖率与 token；
- 把 critic 的 prompt 改严/改松，观察 `verdict_passed` 与修订轮数的变化。

这个练习的意义：面试官问「你调过什么参数、依据是什么」，你有第一手数据。

## 第五步：面试前 3 天

- 抽 `docs/验收题.md` 里的题，每题 90 秒口述（录音回听）
- 准备 3 个「踩坑故事」：Send 编号串号、DeepSeek 400 两次、critic 把好报告打回
- 打开 `reports/` 里最新一份报告和 json，确保能现场解释每个数字
- 录 3 分钟演示（`docs/demo-guide.md` 有分镜）

## 常见追问速查

- 「为什么不用 CrewAI / AutoGen？」——比较维度：状态可控性、断点恢复、
  条件路由的显式程度；以及本项目需要 Send + checkpoint + HITL 三件套。
- 「这个项目最难的点？」——collect 全局重编号 + 审核/质量的雙闸门路由，
  而不是「调用了大模型」。
- 「如果重做会改什么？」——把哈希嵌入换真实 BGE、评测集扩到 50 题并人工标注、
  把 API 状态存 Redis 换掉进程内字典。
