# 学习指南：怎么把这份代码真正变成「你的」

> 代码大部分由 AI 辅助生成，这不可耻——但被追问三层时，你必须答得出来。
> 下面按「跑 → 读 → 写 → 改」的顺序来，每一步都有可检验的产出。

## 第一步：跑起来（半天）

```bash
uv venv --python 3.12 && uv sync --extra dev
.venv/Scripts/python -m pytest -q                                     # 44 个用例全绿
.venv/Scripts/python -m deepresearch.graph                            # 打印流水线拓扑（Mermaid）
.venv/Scripts/python -m deepresearch.ingest data/docs                 # 建索引
.venv/Scripts/python -m deepresearch.main "RAG 和微调应该怎么选？"      # 跑一次真实调研
```

产出：你能不看文档独立跑通，并说清 `data/docs` 里的语料怎么一步步变成报告里的引用。

## 第二步：读代码（2–3 天，按依赖顺序）

| 顺序 | 文件 | 你要能回答 |
|------|------|-----------|
| 1 | `config.py` | 配置从哪来？为什么用 `field(default_factory)` 而不是直接写默认值？ |
| 2 | `state.py` | 每个字段谁写？为什么 `findings` 要 reducer？ |
| 3 | `graph.py` | 节点 / 边 / 条件边各是什么？Send 在哪扇出？放行条件有哪几条？ |
| 4 | `nodes.py` | researcher 为什么只拿 `sub_question`？collect 为什么要重编号？ |
| 5 | `structured.py` | 三种模式区别？降级怎么触发？哪种错误不该被吞掉？ |
| 6 | `retriever.py` + `chunking.py` | 切块策略？本地 / 服务端模式差别？为什么索引是幂等的？ |
| 7 | `checkpointer.py` + `runner.py` | checkpoint 存哪？resume 为什么只跑后半段？ |
| 8 | `api.py` / `mcp_server.py` / `web/app.js` | 为什么用异步任务？MCP 三个工具怎么分工？ |
| 9 | `eval/run_eval.py` | 指标怎么算？消融怎么做？ |

读图小技巧：`python -m deepresearch.graph` 打印的就是真实图对象的拓扑，对着它看
`graph.py` 里的 `add_edge` / `add_conditional_edges`，一眼能对上。

配合 `docs/验收题.md` 自测：遮住答案，口述一遍。

## 第三步：手写重实现（每项 1–2 小时）

闭卷、不看源码，从零写出来，再对照差异：

1. `make_researcher(llm, retriever)` —— 检索、编号、prompt 组装
2. `collect` 节点 —— 排序、去重、两段式重编号
3. `route_after_critic` —— 四个条件 + 轮数封顶
4. `make_verifier` —— 段落切分、引用提取、覆盖率计算
5. `make_human_gate` —— interrupt / resume 语义

写完跑 `pytest` 验证；这五个函数覆盖了项目大部分的追问点。

## 第四步：改一个真实需求（1 天）

选一个，自己动手改，跑测试和评测：

- 把 `data/docs` 换成你熟悉的领域文档（比如某框架官方文档），重建索引，
  看关键词命中率变化，解释为什么；
- 把 `chunk_text` 的 `max_chars` 从 600 改成 300 / 1200，重跑 3 题评测，
  对比覆盖率与 token；
- 把 critic 的 prompt 改严/改松，观察 `verdict_passed` 与修订轮数的变化。

这个练习的意义：被问「你调过什么参数、依据是什么」时，你有第一手数据。

## 第五步：讲之前 3 天

- 抽 `docs/验收题.md` 里的题，每题 90 秒口述（录音回听）
- 准备 3 个「踩坑故事」：Send 编号串号、DeepSeek 400 两次、critic 把好报告打回
- 打开 `reports/` 里最新一份报告和 json，确保能现场解释每个数字
- 录 3 分钟演示（`docs/demo-guide.md` 有分镜）

## 常见追问速查

- 「为什么不用 CrewAI / AutoGen？」——比较维度：状态可控性、断点恢复、
  条件路由的显式程度；以及本项目需要 Send + checkpoint + HITL 三件套。
- 「这个项目最难的点？」——collect 全局重编号 + 审核/质量的双闸门路由，
  而不是「调用了大模型」。
- 「如果重做会改什么？」——把哈希嵌入换真实 BGE、评测集扩到 50 题并人工标注、
  把 API 状态存 Redis 换掉进程内字典。更系统的清单见 `docs/改进计划.md`。
