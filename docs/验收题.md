# 面试验收题（按里程碑累积）

> 用法：每个里程碑结束后先自己答一遍，答不上的去代码/文档里找答案。
> 面试前把这份文件当抽题卡，随机抽 5 道限时口述。

## M2：检索与核验

**1. verifier 的引用覆盖率怎么算？为什么不交给 LLM 判断？**
答：按空行切段落，去掉标题与过短的列表项，正文段落即「结论」；每段用正则
`\[(\d+)\]` 提取引用编号，编号存在于 sources 且不是编造的就是「已引用」；
覆盖率 = 已引用段落 / 结论段落。程序化判定确定、可复现、能进 CI；LLM 自评
会漂移，且同样的输入两次结论可能不同。

**2. 为什么路由要同时看 critic 结论、覆盖率、无效引用？**
答：critic 管「质量观感」，覆盖率管「是否有据可查」，无效编号管「是否编造」。
三者失效模式不同：critic 可能被漂亮的行文骗过；覆盖率低但 critic 满意的情况
真实存在；编造引用必须一票否决。条件全部满足才放行，否则打回重写（有轮数上限）。

**3. 哈希嵌入的局限？生产怎么换？**
答：只做字面相似（字符 n-gram 哈希），不理解语义，同义改写召不回。
嵌入层抽象成 `embed_documents/embed_query`，配好 `EMBEDDING_*` 三项即切换到
OpenAI 兼容的 BGE/text-embedding 服务，检索代码不用改。

**4. API 为什么用「提交 + 轮询」而不是同步阻塞？**
答：一次调研几十秒到几分钟，同步接口会占满连接、超时不可控、无法中途查询进度。
提交后立即返回 run_id，后台任务执行，客户端轮询状态；也便于后续加队列。

**5. 本地嵌入式 Qdrant 和服务端模式的区别？**
答：本地模式 `QdrantClient(path=...)` 把索引存在本地目录，零部署、单进程文件锁，
适合开发/演示/CI；服务端模式连 `QDRANT_URL`，多进程共享、可水平扩展，适合线上。

## M3：并行、人工审核、持久化

**6. Send 扇出后为什么需要 collect？不做重映射会怎样？**
答：每个 researcher 各自从 [1] 编号，合并后编号必然冲突：两个任务都写 [1]，
writer 会引用到错误的来源，verifier 也可能把重复编号当成同一处。
collect 按子问题顺序合并、按 chunk id 去重、把局部编号重映射为全局编号
（两段式占位符替换，避免 [1]→[2] 又被 [2]→[3] 连锁替换）。

**7. max_revisions 的语义？为什么是 `>` 不是 `>=`？**
答：max_revisions 计「修订轮数」，writer 最多跑 1+max 次。critic 每审一次
revisions+1；用 `revisions > max_revisions` 判断，是因为第一轮审查（revisions=1）
在 max=1 时应允许一次修订，第二轮（2）才强制停止。写成 >= 会导致一次修订都跑不了。

**8. HITL 用 interrupt() 的实现原理？暂停期间状态在哪？**
答：human_gate 节点里调用 `interrupt(payload)`，LangGraph 抛出中断并保存当前
状态到 checkpointer，invoke 返回带 `__interrupt__` 的结果；恢复时用
`Command(resume=decision)` 重新进入该节点，interrupt 的返回值就是 decision。
状态在 SQLite/Postgres（按 thread_id），不在内存。

**9. 进程被杀后怎么恢复？为什么新进程只跑 critic？**
答：checkpoint 每步落库；新进程用同一 thread_id 调用 resume，LangGraph 从最后
完成的超级步之后继续，已完成的节点不会重跑。所以恢复后只执行 human_gate 之后
的节点（critic），前端规划/检索/写作不重复花钱。

**10. 为什么 M3 没上 mem0？**
答：M3 已经包含 Send、HITL、持久化三个高风险改动，按计划 mem0 是可裁剪项；
先用 checkpoint 的 thread_id 做「续问」级记忆验证价值，等 M4 评测框架就绪后
再决定是否引入向量记忆并做消融，避免没有评测就堆功能。

## M1：结构化输出与循环控制（回顾）

**11. 三种结构化输出模式的区别？为什么要自动降级？**
答：function_calling 用工具调用约束格式（最精确，但部分端点不支持强制
tool_choice）；json_mode 用 response_format=json_object（需提示词含 json）；
prompted 纯提示词 + 正则抽 JSON（最兼容）。自动降级按错误关键词切换，成功后
记住模式，保证换端点不改代码。

**12. 修订循环怎么防止无限烧钱？**
答：revisions 计数 + max_revisions 封顶；token 计量随报告落盘，评测时可直接
汇总单任务成本；预算敏感场景还可以按上限砍 max_revisions。
